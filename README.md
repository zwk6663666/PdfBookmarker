# PDF 目录书签助手

打开一本 PDF 书籍，程序会自己找到目录页，读出每一条目录的标题、层级和页码，再换算成 PDF 的实际页码，生成可以点击跳转的书签。文字版和扫描版都能处理。识别结果可以在界面里逐条检查和修改，满意后导出新的 PDF，原文件不会被改动。

完整的功能说明见 **[用户手册](docs/用户手册.md)**。

## 运行

**Windows**

1. 电脑上需要有 Python 3.9 或更新版本。没有的话到 https://www.python.org/downloads/ 下载安装，安装时勾选 “Add python.exe to PATH”。
2. 双击 `启动.bat`。第一次运行会自动安装依赖，大约需要几分钟，之后每次双击都会直接打开。

### 打包成 exe

双击 `打包为exe.bat`，按提示选择打包方式。第一次会自动建立一个专用的精简打包环境 `.venv-build`，需要几分钟，以后就不用再装了。

| 方式 | 结果 | 特点 |
| --- | --- | --- |
| 1 文件夹版 | `dist\PdfBookmarker\PdfBookmarker.exe` | 启动最快，分发时要复制整个文件夹 |
| 2 单文件版 | `dist\PdfBookmarker-Portable.exe` | 只有一个 exe，方便发给别人；每次启动要先解压到临时目录，会慢几秒，期间显示启动画面 |
| 3 两种都打包 | 以上两者 | |

也可以直接带参数运行，跳过选择，例如 `打包为exe.bat 2`。两种结果都不需要对方电脑安装 Python。

为了控制体积，打包时做了这些处理：

- 打包环境只装必需的库，用不带界面的 OpenCV 和只含基础模块的 PySide6-Essentials，不会把日常环境里的其他库带进去。
- `PdfBookmarker.spec` 会剔除用不到的部分，包括 Qt 的翻译文件和多余插件、软件 OpenGL 渲染器、OpenCV 的视频解码库、Pillow 的 AVIF 插件、PyMuPDF 的版面分析插件，以及 scipy、pandas 等被顺带引用的大型库。
- 没有使用 UPX 压缩。它能再小一些，但容易被杀毒软件误报，也可能损坏 Qt 的动态库。

打包结束时脚本会显示两种结果各自的大小。

**macOS / Linux**

在终端运行 `bash 启动.command`，或者手动执行：

```
python3 -m pip install -r requirements.txt
python3 app.py
```

## 使用

1. 把 PDF 拖进窗口，或点“打开 PDF”。程序会马上开始识别，文字版一般一两秒，扫描版视电脑性能大约 10 到 30 秒。
2. 左侧是识别出的书签树，右侧是页面预览。点任意一条书签，右侧就跳到它指向的页面，文字版还会把标题标成黄色，一眼就能看出位置对不对。
3. 发现不对的地方可以直接改：
   - 双击标题、书中页码或 PDF 页码即可修改。
   - 拖动条目可以调整顺序，拖到另一条上面会成为它的子项。
   - 工具栏里有新增、删除、上移、下移、升级、降级。
   - 如果整本书的页码都差了几页，只要改右上角的“页码偏移”，所有条目会一起变化。
   - 某一条位置不对时，在右侧翻到正确的页，再点“定位到当前页”。
   - 条目很多需要大改时，用“文本编辑”以纯文本方式整体修改。
   - 所有修改都可以用 Ctrl+Z 撤销，Ctrl+Y 重做。
4. 点“用阅读器预览”会用系统默认的 PDF 阅读器打开一个临时文件，可以看到书签在真实阅读器里的样子。
5. 确认无误后点“导出 PDF”（Ctrl+S）保存。

### 状态列的含义

| 状态 | 含义 |
| --- | --- |
| 已校验 | 在正文对应页找到了这个标题，页码可信 |
| 已修正 | 按偏移算出的页上没有这个标题，但在前后一两页找到了，已自动调整 |
| 待确认 | 目录里这一条没有页码（比如篇名），暂时沿用了下一条的页码 |
| 手动 | 你改过的条目 |
| 空白 | 没能在正文中核对，多见于扫描版 |

文字版在识别时会自动逐条核对。扫描版的核对需要逐页 OCR，比较慢，所以放在“更多 › 核对页码”里，需要时再手动运行。

## 识别不理想时

- **没找到目录页**：取消勾选顶栏的“自动识别”，在“目录页”处填上目录所在的 PDF 页码范围，再点“重新识别”。
- **文字版的标题是乱码**：有些 PDF 的文字层编码有问题，在“识别设置”里勾选“强制使用 OCR”后重新识别。
- **页码整体错位**：调整“页码偏移”。偏移的意思是 PDF 页码等于书中页码加上这个数。
- **前言等用罗马数字编页的部分**：程序会单独推算这部分的页码，如果不准，选中后用“定位到当前页”修正。
- **扫描版目录 OCR 错字多、层级乱**：可以改用大模型识别，见下一节。

## 大模型识别（可选）

默认完全在本机识别。如果想让视觉大模型读取目录页，在“识别设置”里把“识别引擎”改成“大模型识别”，再点“接口设置…”：

- **接口**：下拉选择 OpenAI、Claude、Gemini、通义千问、智谱、豆包、Kimi、硅基流动、OpenRouter、Ollama（本机），或选“自定义”后自己填写接口地址并选择协议（OpenAI 兼容 / Anthropic）。
- **API 密钥**、**模型**：模型可从下拉选择，也可以直接输入，需要是支持图片输入的模型。可点“测试连接”检查配置。

只有目录页的图片会发给大模型；查找目录页、推算页码偏移仍在本机完成。大模型调用失败时会自动改用本地识别结果，并在状态栏说明原因。密钥保存在本机的程序设置里。

## 实现说明

| 文件 | 内容 |
| --- | --- |
| `app.py` | 图形界面（PySide6） |
| `core.py` | 目录识别和书签写入，和界面无关，也可以在脚本里直接调用 |

识别过程大致如下：

1. 每一页先尝试读取文字层，文字层为空或是乱码时改用 RapidOCR 识别。RapidOCR 完全离线运行，不需要联网，对中文识别效果好。
2. 在书的前 40 页里找目录页（找不到时再看最后几页）。目录页的特征是有“目录 / Contents”标题，或者大部分行的行尾是页码且页码逐渐增大。扫描版会先只做文字框检测，看页面右侧有没有一列对齐的页码，只对可能是目录的页做完整识别，这样能省下大部分时间。
3. 对扫描版的目录页再精读一遍：每个文字框用更高分辨率重新识别，单独补读容易漏掉的小号编号（如 2.1）和一位数页码。
4. 把每一行拆成标题和页码，跨行的长标题会合并。层级优先按编号判断（第X篇、第X章、第X节、1.1、1.1.1、一、（一）等），没有编号的条目按缩进判断，前言、参考文献、索引等放在第一级。
5. 读取正文页眉页脚上印的页码，推算 PDF 页码与书中页码的差值。读不到时改用章节标题在正文中出现的位置来推算。
6. 逐条到正文中查找标题，确认或修正每一条的页码。

可以单独调用核心模块：

```python
import core
res = core.recognize("book.pdf")
toc = [[e.level, e.title, e.pdf_page(res.offset)] for e in res.entries]
core.export_pdf("book.pdf", "book_书签.pdf", toc)
```

依赖：PyMuPDF、PySide6、numpy、rapidocr_onnxruntime。
